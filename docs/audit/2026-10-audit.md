# Audit de SpaceNotch — octobre 2026 (v1.13.1)

Audit à 360° mené en lecture seule après la vague 7, sur quatre angles : **architecture et santé du
code**, **performance et budget d'image**, **états, gestes et mouvement**, **intégration système,
accessibilité, réglages et installeur**. Il se termine par une spécification (RFC) de la notch et un
plan d'exécution **à valider avant toute refactorisation**.

Décisions de l'auteur, prises avant l'audit :

- la gestion des activités simultanées (notch scindée, file d'attente) **reste telle quelle** ;
- la physique de ressort **reste telle quelle** ;
- le modèle d'ouverture est **à définir par l'audit**, d'après le fonctionnement réel des états ;
- périmètre : fenêtre principale, performance des animations, réglages et installeur, accessibilité.

Légende de sévérité : 🔴 critique · 🟠 haute · 🟡 moyenne · ⚪ basse.

#### 2.3.1 Recommandation pour l'ouverture

**Le clic reste le geste principal**. C'est la convention Windows : rien ne change sous le pointeur sans intention. Et la notch est collée au bord supérieur, là où passe la souris pour atteindre les onglets et les menus. On y ajoute un geste naturel qui ne se bat avec aucun autre : **tirer pour ouvrir**.

| Geste | Effet | Réglage |
|---|---|---|
| Survol 350 ms | Aperçu (ou visage heure·météo sans activité) | « Aperçu au survol », activé |
| Survol 800 ms | Ouvre | « Ouvrir au survol », désactivé |
| Clic | Ouvre / referme (recherche s'il n'y a rien) | — |
| **Tirer vers le bas 12 à 39 px, puis lâcher** | **Ouvre**, avec la vitesse du geste transmise au ressort d'ouverture | nouveau, toujours actif |
| Tirer au-delà de 40 px | Détache (inchangé) | « Détacher en tirant » |
| Lâcher sous 12 px | Rien (tolérance du clic) | — |
| Tirer vers le haut sur la notch ouverte | Referme | nouveau |
| Double-clic | Note | — |
| Clic droit / **appui long** | Menu rapide | appui long nouveau |
| Molette / Ctrl + molette / clic milieu | Activités / pile / lecture-pause | — |
| Alt + Espace | Recherche | — |

Le seuil de 40 px sépare déjà « s'étirer » et « s'arracher » : on donne un sens à la zone du milieu. La notch suit la main, puis se déplie dans le prolongement du geste. Rien d'autre ne change.

## 3. RFC — composant Notch

### 3.1 Objectif

Rendre l'état de la notch **explicite, testable et unique**. Aujourd'hui il est réparti entre `IslandStateManager` (5 états), `IslandController` et une trentaine de drapeaux de la fenêtre. Le comportement visible est conservé : scission, file d'attente, ressorts et visages ne changent pas.

### 3.2 Machine à états hiérarchique (régions orthogonales)

```
NotchMachine
├─ Présence      : Visible | Retirée(plein écran) | Arrêtée
├─ Placement     : Attachée(haut) | Onglet(bord) | Flottante
│                  └─ Glisser : Appui → Traction(0–39 px) → Arrachement(≥ 40) → Déplacement → Atterrissage
├─ Surface       : Repos → Aperçu → Ouverture ↔ Ouverte → Repli
│                  └─ Repos.Visage : Yeux | Heure·météo | Assoupi | Passage(activité)
└─ Superpositions (indépendantes, cumulables) :
                   Annuler · AideGestes · MenuRapide · Bulle · Visite
```

- **Présence** stoppe tout ce qui vit (minuteurs, rendu) quand la notch est retirée : le bogue §2.1 n°2 devient impossible par construction.
- **Placement / Glisser** remplace `_dragPhase`, `UsesSideTab`, `UsesFloatingGeometry`.
- **Surface** reprend `IslandState` et y ajoute `Repli → Aperçu`.
- **Repos.Visage** remplace `_restFace`, `_morphTarget`, `_dozing`, `_restFaceShown`.

### 3.3 Interfaces (Core, sans dépendance)

```csharp
public enum NotchTrigger { HoverEnter, HoverDwell, HoverLeave, Click, DoubleClick, SecondaryClick,
    LongPress, PullMoved, PullReleased, Wheel, HotKey, Escape, ActivityArrived, ActivityEnded,
    Idle, Wake, FullscreenEntered, FullscreenLeft, AnimationSettled }

public sealed record NotchInput(NotchTrigger Trigger, double PullDip = 0, double Velocity = 0,
    int WheelDelta = 0, ModifierKeys Modifiers = default, string? ActivityId = null);

public sealed record NotchSnapshot(Presence Presence, Placement Placement, Surface Surface,
    RestFace Face, Overlays Overlays, string? PresentedActivityId, IslandFootprint Target);

public interface INotchMachine
{
    NotchSnapshot Current { get; }
    NotchStep Fire(NotchInput input, TimeSpan now);   // pur : aucun effet de bord
}

public sealed record NotchStep(NotchSnapshot Next, IReadOnlyList<NotchEffect> Effects);

public abstract record NotchEffect   // exécutés par la fenêtre, dans l'ordre
{
    public sealed record AnimateTo(IslandFootprint Target, double InitialVelocity) : NotchEffect;
    public sealed record StartHandoff(string ActivityId) : NotchEffect;
    public sealed record SetLife(bool Running) : NotchEffect;      // minuteurs de Pixel
    public sealed record Announce(string Text) : NotchEffect;       // Narrateur
    public sealed record OpenScene(string SceneKey) : NotchEffect;
    public sealed record Cue(SoundCueKind Kind) : NotchEffect;

```

La fenêtre devient un **interpréteur d'effets**. Toute la logique de transition se teste en Core avec une horloge simulée, comme `PixelHandoff` et `PixelVitals`. La visite filmée injecte des `NotchInput` au lieu de manipuler les champs.

### 3.4 Pipeline d'animation

1. **Une seule horloge d'image** (`FrameClock`, un abonnement à `CompositionTarget.Rendering`) qui ne tourne que si au moins un canal est en mouvement. Les quatre abonnements actuels (ressort, glisser, visage, passage) deviennent des canaux.
2. **Canaux de ressort** (Core) : forme (largeur, hauteur), traction, et pour chaque pixel de passage (x, y, largeur, hauteur). Une nouvelle cible conserve la position et la vitesse : l'interruption est native.
3. **Enveloppe de fenêtre** : au démarrage d'un canal de forme, la fenêtre prend l'enveloppe maximale prévue (cible ∪ actuel ∪ dépassement estimé par le solveur). Elle n'est plus redimensionnée avant l'arrêt. Le halo suit en composition.
4. **Rendu** : la géométrie de la silhouette n'est reconstruite que si la forme a bougé de plus de 0,25 DIP.
5. **Réduction des animations** : le canal saute à sa cible (`SnapTo`), en un seul point de décision.

### 3.5 Hors périmètre

Pas de nouvelle physique, pas de nouveau mode de scission (décisions de l'auteur). Pas de changement visuel des scènes, à part l'accessibilité.
